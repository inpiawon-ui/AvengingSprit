## A. 게임 필러 (무엇을 주는 게임인가)

| 항목 | 내용 |
|------|------|
| 한 줄 컨셉 | 방 기반 로그라이크 액션에 **빙의(Possess)** 를 결합해, **어떤 몸을 뺏었는가가 빌드를 결정**하는 세로형 모바일 액션 RPG |
| 핵심 재미 | **적을 죽이는 게 아니라 적이 되는 것.** 눈앞의 위협이 곧 다음 무기 |
| 핵심 감정 | 취약함(고스트) → 탈취의 쾌감(빙의) → 상실(육체 소멸) → 재탈취. **잃어도 끝나지 않는다** |
| 핵심 행동(코어 동사) | **빙의한다 · 싸운다 · 잃는다 · 다시 빙의한다** |
| 세션 형태 | 실시간 오토어택. 1 런 3~5분 · 1 룸 30~45초. 세로 한손 조작 |
| 성공 기준(플레이어 관점) | 호스트를 잃어도 당황하지 않고 **다음 몸을 고르는 판단**이 서는 상태 |
| 차별점 | Archero류는 **장비·스킬**이 빌드를 만든다. 이 게임은 **필드의 적 자체**가 빌드다. 죽음이 페널티가 아니라 **전환 수단** |

> 🔒 **아트 제1원칙**: 1991 Jaleco 아케이드 원작의 감성 재현이 최우선. 모던함과 충돌하면 원작을 택한다.

## C. 콘텐츠 관계 (루프) — 게임 구성의 핵심

### C-1. 코어 루프 (30~45초 · ROOM 단위)

```
룸 입장 → 오토어택 교전 → [호스트 사망 시] 고스트 복귀 → 근처 적에게 재빙의
   → 전멸 → 룸 클리어 → 버프 3택1 → 다음 룸
```
**축**: 콘텐츠 1·2·3·5·6 | **핵심**: 호스트 사망이 실패가 아니라 **빌드 전환점**이다.

### C-2. 런 루프 (3~5분 · STAGE 단위)

```
로비 → [스태미나 ⚡5 소모] → 호스트 선택 → STAGE 도전 → C-1 반복 ×6룸
   → 보스 → 클리어 → 보상(골드·EXP·강화재료) → 로비 복귀
```
**축**: 콘텐츠 4·12·13·22 | **핵심**: 호스트 선택이 **STAGE마다 반복**된다. 매 런의 시작 결정.

### C-3. 성장 루프 (일 단위)

```
런 보상 누적 → 호스트 강화 / 고스트 강화 → 진행도 상승
   → 신규 호스트 해금 → 새 플레이스타일 → 더 깊은 STAGE
```
**축**: 콘텐츠 7·8·9·10 | **핵심**: **모든 영구 해금은 게임플레이로.** 결제 해금 없음.

### C-4. 수익·표현 루프

```
골드·젬 획득 → 코스튬 / 배틀패스 / 편의 팩 구매 → 표현 만족
   → 계속 플레이 → 시즌 갱신 → 재구매
```
**축**: 콘텐츠 14·15·16·17 | **핵심**: **전투력을 팔지 않는다.** 표현과 편의만 판다.

### C-5. 리텐션 루프

```
이탈 → 스태미나 자연 회복 / 일일 보상 / 시즌·이벤트 갱신
   → 복귀 유인 → C-2 재진입
```
**축**: 콘텐츠 18·19·20·21

### 루프 간 연결

```
        ┌──────────── C-5 리텐션 ────────────┐
        ↓                                    │
     C-2 런 ──보상──→ C-3 성장 ──해금──→ C-2 (더 깊이)
        │                  │
      C-1 코어           C-4 수익·표현 (병렬, 전투력 무관)
```

## D. 기둥 결정 현황

| 결정 축 | 상태 | 메모 |
|--------|------|------|
| 카메라 뷰 · 조작 | ✅ **확정** | 완전 탑다운 + 가상 조이스틱 + 오토어택. `JUMP`→`DASH`(패시브 회피 스탯) |
| 승패 / 수명 구조 | ✅ **확정** | 고스트 HP 0 = 런 종료. **호스트 사망은 런 종료가 아님** |
| 과금 범위 | ✅ **확정** | 가챠 없음 · SSR 없음 · 코스튬/배틀패스/편의만. 페이투윈 없음 |
| 호스트 수·해금 | ✅ **확정** | 12종. `amazoness` 시작 보유, 나머지 11종은 진행도 해금 |
| 진행 단위 | ✅ **확정** | `CHAPTER`(3) > `STAGE`(30/챕터) > `ROOM`(6/스테이지) |
| 온라인 / 소셜 | ✅ **확정** | **멀티플레이 없음.** 랭킹·친구는 P2, 서버 착수 시점에 재판단 |
| 데이터 저장 | ✅ **확정** | 로컬 우선. 저장소 인터페이스 경유 → 추후 서버 구현체 교체 |
| 아트 방향 | ✅ **확정** | 1991 원작 감성 최우선 · HD 픽셀아트 · 9:16 720×1280 네이티브 · 하이브리드 폰트 |
| 플랫폼 | ✅ **확정** | 모바일(iOS/Android) 우선. **Steam은 후순위 분리** |
| 스태미나 수치 | ⚠️ **미정** | 목업 `30/30` · 1런 `⚡5` = 6런/충전. 회복 속도·상한 미정 → Stage 2 |
| 원작 스프라이트 참조 | ⚠️ **미정** | IP 계약 범위 확인 중. **일단 목업 기준으로 진행** |

## F. 다음 단계

**게이트 A 승인 후** 콘텐츠별 세부 기획(Stage 2) 착수.

1개월 목표(1차 범위)에 맞춰 **세부 기획 권장 순서**:

```
1순위 (1차 범위 · Stage 2 → 2b 즉시 진행)
   ① 로비(HUB)        — 허브. 다른 모든 콘텐츠의 진입점
   ② 호스트 선택       — 12칸 로스터 · 잠금 표현 · 빙의 시작
   ③ 타이틀            — 가장 단순. 목업 없어 신규 설계

2순위 (1차 범위 밖 — 1차 완료 후)
   ④ 빙의 전투 · ROOM 진행 → ⑤ 보스 · 버프 → ⑥ 성장 → ⑦ 수익화 → ⑧ 리텐션
```

> ⚠️ 1차 범위 3개 콘텐츠만 Stage 2 → 2b(화면 설계 + 박스 목업 + 에셋 매니페스트)까지 내리고,
> **Stage 3(씬·프리팹)** 으로 넘어가 **실행되는 프로토타입**을 먼저 만든다.
> 나머지 콘텐츠는 프로토타입이 돌아간 뒤 살을 붙인다.
