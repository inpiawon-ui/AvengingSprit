## 6. 데이터 설계 제약 (서버 전환 대비 — 필수)

1. 유저 데이터 접근은 **저장소 인터페이스를 경유.** 게임 로직이 로컬 파일을 직접 읽지 않는다
2. **로컬 구현체 → 서버 구현체 교체만으로** 전환되어야 한다
3. 마스터 테이블은 **테이블 SO 하나에 배열** (개별 `.asset` 금지)
4. 재화·진행도 갱신 경로는 **한 지점에 집약**
5. `UserData`에 **`saveVersion` 필수.** `unlockedHostKeys`는 저장하지 말고 progress로 매번 평가

## 9. 피격 동작 — 적용 후 재판단 (배치 1 테스트 항목)

**우려**: 피격 프레임이 들어가면 공격이 끊겨 보인다.

지금 코드가 정확히 그렇게 동작한다 — `Unit.TakeDamage` → `PlayHit()` 이 **재생 중인 공격을 잘라 먹는다**
(`PlayAttack` 은 피격 중이면 물러나는데, 반대 방향 보호는 없다).
람보처럼 연사가 빠른 호스트가 집중 사격을 받으면 공격 2프레임이 계속 잘려
"쏘는 자세가 안 나온다"로 보일 수 있다. 배치 1 테스트에서 이 지점을 본다.

판단 후 고를 수 있는 세 단계 — **그림은 어느 쪽이든 그대로 쓴다**. 재생 규칙만 바꾼다.

| | 동작 | 비용 |
|---|---|---|
| 가 | 지금 그대로. 피격이 공격을 자른다 | 0 |
| 나 | 피격 프레임은 **공격 중이 아닐 때만** 재생. 공격 중엔 붉은 점멸만 | 분기 1줄 |
| 다 | 피격 프레임을 아예 안 씀. 붉은 점멸로만 알림 | 분기 1줄 |

**그래서 `hit` 5장은 계속 받는다.** 방향당 1장이라 캐릭터당 5장뿐이고,
나중에 켜기로 결정했을 때 그림이 없으면 15종을 다시 돌려야 한다.
안 쓰기로 해도 손실은 5장 × 15종이고, 적 유닛 쪽에서는 공격이 성기므로 그대로 쓸 여지가 있다.
