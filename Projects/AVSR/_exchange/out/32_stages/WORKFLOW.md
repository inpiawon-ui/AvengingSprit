# 스테이지 배경 제작 워크플로우

방 배경 **24장**(일반 18 + 보스 6)을 같은 방식으로 만든다.
한 장이 이미 통과했으므로(`roomfloor_ch1_twin_platform`) 그것을 기준으로 반복한다.

---

## 0. 정본 (한 장이면 끝난다)

```
32_stages/APPROVED_roomfloor_ch1_twin_platform.png
```

**이 그림이 모든 배경의 기준이다.** 색·재질·명암·벽 구조·배관·문 모양을 여기서 가져온다.
방마다 다른 것은 **바닥 무늬와 벽 장식뿐**이고, 규격은 24장이 전부 같다.

`32_stages/grid_check_overlay.png` — 정본에 격자를 얹어 확인한 것. 줄눈 위치 확인용.

## 1. 규격 (24장 공통 · 예외 없음)

| 항목 | 값 |
|------|-----|
| 캔버스 | **720 × 936 px** |
| 안쪽 바닥 영역 | 왼위 `(72, 144)` ~ 오른아래 `(648, 864)` |
| 바닥 격자 | **한 칸 36 × 36 px · 가로 16칸 × 세로 20칸** |
| 세로 줄눈 x | 72 부터 36 px 마다 (72 · 108 · 144 · … · 648) |
| 가로 줄눈 y | 144 부터 36 px 마다 (144 · 180 · 216 · … · 864) |
| 위쪽 문 구멍 | 폭 216 px · 높이 180 px · 왼쪽 끝 x = 252 |
| 원근 | **없다.** 정사영. 모든 칸이 같은 크기, 줄눈은 화면 축과 평행 |
| 평균 명도 | **30 이상** (정본 33.6 · 상위10% 50.8) |

> 지금 있는 17장은 **720×1530** 이라 못 쓴다. 방이 936 이라 세로 61 %로 눌려
> 정사각 타일이 납작해지고 원이 타원이 된다. 평균 명도도 8~26 이라 화면이 새까맣다.

## 3. 챕터별로 달라지는 것

챕터가 올라가면 **색과 벽 장식만** 바뀐다. 격자·구조·문은 그대로다.

- CH1 — 정본 그대로 (유령 연구소)
- CH2 — 사장님이 방향을 정해 주시면 그 지시를 따른다
- CH3 — 같음

색·분위기는 **사장님이 정한다.** 규격만 위 표를 따르면 된다.

## 4. 납품 · 검수 절차

```
① _exchange/in/ 에 평평하게 납품 (폴더 만들지 말 것, 파일명 그대로)
② 완료 통보
③ 내가 `Tools/Game/납품 반영` 실행 → 해시 대조 후 반영
④ 내가 계측 → 통과 / 반려
```

### 내가 재는 것 (전부 숫자로만 본다)

| 항목 | 기준 |
|------|------|
| 캔버스 | 720 × 936 정확히 |
| 세로 줄눈 위상 | `x ≡ 0 (mod 36)` · ±1 px |
| 가로 줄눈 위상 | `y ≡ 0 (mod 36)` · ±1 px (144 기준) |
| 격자 균일성 | 위아래 폭 차이 ±1 px (원근 없음 확인) |
| 평균 명도 | 30 이상 |
| 문 구멍 | x 252~468 · y 0~180 안에 뚫려 있을 것 |

"예쁜지"는 판단하지 않는다. 위 여섯 개만 본다.

### 반려는 이렇게 나간다

31차 때처럼 **틀린 항목 하나와 고칠 값**만 적어 보낸다.
예: "세로 줄눈이 `x ≡ 22` 다. 안쪽 바닥을 가로로 +14 px 밀면 맞는다."

---

## 5. 한 번에 몇 장씩

**챕터 하나씩(6장)** 이 좋다. 규격이 어긋나면 6장이 같이 어긋나므로
첫 장을 먼저 받아 계측하고, 통과하면 나머지 5장을 이어 받는다.

권장 순서:
1. CH1 나머지 5장 → 통과 확인
2. CH2 6장
3. CH3 6장
4. 보스 6장

## 6. 지금 게임은 어떻게 돌고 있나

배경이 채워지는 대로 그 상수를 지우면 방마다 제 배경이 뜬다.

# 부록 — 무대 단위로 바뀌었다 (2026-08-25)

**지형(Template)별 배경은 만들지 않는다.** 재 보니 화면에서 구별이 안 됐다.

```
CH1 지형 6장이 서로 다른 정도 (평균 픽셀차)   0.09 ~ 3.37
  └ pillar_cross 는 twin_platform 과 사실상 같은 그림 (0.09)
무대가 바뀌면                                 14 ~ 25
```

눈에 보이는 축은 **무대**뿐이다. 지형 차이는 배경이 아니라 그 위에 얹히는
장애물 배치가 만든다. 그래서 배경은 **무대 한 장**으로 깐다.

규격은 위 1절과 같다. 코드에서는 `BattleDirector.FloorKeyOf` 의 구간만 손대면 된다.

# 부록 2 — 배치 순서 (2026-08-25 결정)

지형지물을 한꺼번에 다 넣지 않는다. **단계를 나눈다.**

## 1단계 (지금) — 기본 방해물만

| 역할 | 종류 |
|------|------|
| 길을 막는 것 | `block` · `pillar` · `rail` · `crate` · `bulk` · `low_cover` · `barricade` |
| 밟으면 아픈 것 | `timed_spike` |

이것만으로 방의 뼈대가 잡힌다. 격자·통행·시야가 여기서 결정된다.

## 2단계 (나중) — 움직이는 함정

`ROTATING_BLADE`(톱니) · `SWING_HAMMER`(해머) · `TURRET` · `LASER`.

**종류·그림·회전 로직은 이미 다 있다.** 배치만 안 한다.
지금 섞으면 방이 어려운 이유가 지형 때문인지 함정 때문인지 구분이 안 된다.
기본 배치가 자리를 잡은 뒤에 **스테이지별로 어디에 몇 개**를 정한다.

되돌리는 법: `RoomImporterV33.PropKindsFor` 의 해당 구간 목록에
`"ROTATING_BLADE"` 를 더하고 임포터를 다시 돌리면 끝이다.
