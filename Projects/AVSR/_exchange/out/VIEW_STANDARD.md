# 시점 기준 (VIEW STANDARD)

**앞으로 나오는 모든 인게임 그림은 이 문서의 각도를 따른다.**
지금까지 그림마다 각도가 달라서 화면이 어긋나 보였다 — 이 문서가 그걸 끝내기 위한 것이다.

---

## 무엇이 문제였나

같은 화면 안에 **세 가지 다른 시점**이 섞여 있었다.

```
바닥 (roomfloor_ch1_*)  90° 완전 수직 탑뷰. 원근이 전혀 없다
기둥 (obj_pillar)        45° 아이소메트릭 큐브. 윗면·좌면·우면이 균등하게 보인다
캐릭터 (unit_*)          거의 정면. 위에서 본 각이 아니다
```

셋이 한 화면에 있으면 어느 것도 바닥에 붙어 있는 것으로 안 보인다.

---

## 기준 — 카메라를 **65°** 로 눕힌 탑뷰

수직(90°)도 아니고 아이소메트릭(45°)도 아니다.

```
카메라 각도   지면에서 65°  (= 바로 위에서 25° 기울어짐)
Y 회전        0° — 좌우로는 안 돌린다
```

**Y 회전이 0이라는 것이 아이소메트릭과의 결정적 차이다.**

```
아이소메트릭(45° + Y 45°)    바닥 격자가 ◇ 마름모.  물체는 윗면·좌면·우면 3면
우리 기준   (65° + Y 0°)     바닥 격자가 □ 정사각.  물체는 윗면·앞면 2면
```

물체를 그릴 때 **옆면(좌·우)이 보이면 틀린 것이다.** 윗면과 앞면 둘뿐이다.

---

## 물체 그리는 법 — 1 m 블록 기준

우리 화면은 **1 m = 72 px** 이다.

```
바닥에 닿는 자리   72 × 72 px 정사각형 (이 칸을 차지한다)
캔버스            72 × 102 px
바닥 접촉선        캔버스 **맨 아랫변**
```

캔버스 안에서:

```
   ┌──────────┐  ← 캔버스 위쪽 30 px = 윗면
   │  윗면     │     살짝만 보인다. 65° 라서 납작하게 눌린다
   ├──────────┤
   │           │
   │  앞면     │  ← 아래 72 px = 앞면. 이쪽이 크게 보인다
   │           │
   └──────────┘  ← 이 변이 바닥에 닿는다
```

**윗면 : 앞면 = 대략 3 : 7.** 이 비율이 65° 의 얼굴이다.
- 윗면이 더 크면 위에서 내려다보는 탑뷰가 되고(원근이 죽는다)
- 앞면이 더 크면 옆에서 보는 횡스크롤이 된다

---

## 그림자

모든 서 있는 물체·캐릭터는 발밑에 그림자를 갖는다.

```
모양    가로:세로 = 10 : 3 으로 눌린 타원
색      어두운 남색 단색 (반투명 아님 — 이진 알파)
위치    바닥 접촉선 위에 걸친다
```

이미 `guru`(부양) 규격에서 쓰던 것과 같다.

---

## 그리면 안 되는 것

```
✗ 좌면·우면이 보이는 큐브        → 아이소메트릭이다
✗ 윗면만 보이는 납작한 타일      → 수직 탑뷰다
✗ 소실점이 있는 원근 (위아래 폭이 다른 것)  → 우리는 정사영이다
✗ 물체마다 다른 광원 방향
```

**광원은 화면 위쪽에서 온다.** 윗면이 가장 밝고, 앞면이 한 단계 어둡고, 그림자가 가장 어둡다.

---

## 캐릭터

원작 1991년 시트를 쓰는 캐릭터 23종은 **지금 당장 바꾸지 않는다.**
IP 가 이 게임의 이유고, 원작 그림을 다시 그리는 것은 그 취지에 어긋난다.

다만 원작 캐릭터는 실제로 이 기준과 크게 어긋나지 않는다 —
정면을 보고 서 있고 발밑이 보인다. 바닥과 물체를 이 기준으로 맞추면
캐릭터가 따로 놀던 문제의 대부분이 사라진다.

캐릭터를 손볼지는 바닥·물체가 바뀐 화면을 보고 판단한다.
