# [AVSR] 57차 발주 — 보스 예고 3장 (보스 6 · 예고 4겹)

## 이번엔 3장뿐이다 — 왜 적은지 먼저

보스 6 발주(패턴 24개)를 짓는 중인데, **그림이 필요한 곳이 거의 없다.**

```
보스 그림 6종 × 21장          이미 있다
unit_{보스}_s_tell 6종        이미 있다 (코드가 한 번도 안 불렀을 뿐)
이름표 배경                    hud_action_frame 재사용
바닥 위험 도형 24종            ❌ 그림으로 만들면 안 된다 — 아래
```

### 바닥 도형을 발주하지 않는 이유

발주서 §3 [R1] 이 못박은 것:

> **예고를 그리는 도형과 판정하는 도형이 같은 것이어야 한다.**
> 따로 만들면 "분명히 피했는데 맞았다" 가 나온다.

24개 패턴의 매개변수가 전부 다르다 — 부채꼴 120°·180°, 반경 2.5~8 m,
고리 4.5 → 1.5 m 로 조여듦, 3줄 레인, 4분면 회전. 스프라이트로는 못 따라간다.
따라가려고 그림을 24장 그리면 **그림과 판정이 갈라져서 정확히 R1 이 막으려던 버그가 난다.**

그래서 도형은 코드가 그린다(절차적 메시). 같은 숫자 한 벌로 그리고 판정하므로
어긋날 수가 없다.

**대신 그 도형을 무엇으로 채울지**가 그림 몫이다. 그게 이번 3장이다.

## 1. `fx_danger_hatch` — 위험 구역 채움 (64×64)

보스가 예고할 때 **맞는 자리**를 바닥에 칠하는 무늬.

| 항목 | 값 |
|---|---|
| 크기 | 64×64 |
| 색 | 붉은 계열 |
| 무늬 | **45° 빗금.** 선 굵기 6px · 간격 16px |
| 타일링 | **상하좌우 전부 이어져야 한다** |

- 코드가 임의 도형(부채꼴·고리·레인·4분면)을 만들고 그 안을 이 무늬로 채운다.
  **어느 방향으로 잘려도 무늬가 이어져야** 하므로 상하좌우 4방향 전부 심리스여야 한다.
- 빗금이 45° 인 이유: 가로·세로 줄은 레인 패턴(세로 3줄)과 겹쳐 읽혀 혼동된다.
- 배경(빈 칸)은 투명이다. 바닥이 비쳐야 어디인지 알 수 있다.

## 2. `fx_safe_hatch` — 안전 구역 채움 (64×64)

**"저기 맞겠네" 보다 "저기로 가면 되네" 가 훨씬 빨리 읽힌다.** 위험만 그리면 부족하다.

| 항목 | 값 |
|---|---|
| 크기 | 64×64 |
| 색 | 초록 계열 |
| 무늬 | **위험과 반대 방향 45° 빗금** (`\` 대 `/`) |
| 타일링 | 4방향 심리스 |

- ⚠ **위험 무늬와 방향이 반대여야 한다.** 색만 다르면 색약인 사람에게 같은 그림이고,
  겹치는 경계에서 어느 쪽인지 안 읽힌다. 기울기가 다르면 흑백으로도 갈린다.
- 선을 위험보다 **가늘게**(4px) 잡는다. 안전지대가 더 조용해야 눈이 위험으로 간다.

## 3. `ui_dodge_arrow` — 회피 화살표 (48×48)

안전한 쪽을 가리킨다. 8종 방향(뒤로·옆으로·틈으로·직각으로·안전지대로·붙어라·갈아타라·쏘지마라)이
전부 이 한 장을 **코드가 돌려서** 쓴다.

| 항목 | 값 |
|---|---|
| 크기 | 48×48 |
| 방향 | **오른쪽(+x) 한 방향만** — 회전은 코드가 한다 |
| 색 | 흰색~밝은 노랑 (구역 무늬 위에 얹히므로 둘 다와 대비돼야 함) |

- ⚠ **`possessmark_arrow` 와 확실히 달라야 한다.** 그쪽은 "저 몸을 빼앗아라" 이고
  이쪽은 "저리로 피해라" 다. 킹핀 「처형 표식」에서 **둘이 같은 화면에 동시에 뜬다** —
  거기서 헷갈리면 몸을 갈아타야 할 때 도망치게 된다.
  기존 것은 32×32 얇은 삼각형이므로, 이번 것은 **굵고 꼬리가 있는 화살표**로 간다.
- 회전 중심이 캔버스 정중앙(24, 24)이어야 한다. 어긋나면 돌릴 때 흔들린다.

## 확인 기준

1. 3장 모두 지정 크기와 정확히 일치 (64×64 · 64×64 · 48×48)
2. 알파가 0 과 255 뿐 (반투명 픽셀 0개)
3. 안티에일리어싱 없음 — 색 경계가 계단이다
4. `fx_danger_hatch` · `fx_safe_hatch` 를 **상하좌우로 이어붙여도 이음매가 안 보인다**
5. 두 무늬의 **빗금 기울기가 서로 반대**다 (흑백으로 바꿔도 구별된다)
6. `ui_dodge_arrow` 가 `possessmark_arrow` 와 한눈에 다르다
7. `ui_dodge_arrow` 의 회전 중심이 캔버스 정중앙이다
