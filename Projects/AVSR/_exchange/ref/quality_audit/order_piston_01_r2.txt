API 키를 쓰는 CLI 폴백은 쓰지 마라.

너는 아트 디렉터(주)다. 네 시안 `Projects/AVSR/_exchange/ref/quality_audit/mock_piston_01.png` 의 생김새 · 상태 판독은 좋다. 개발 담당(보조)이 **축척 오류** 하나를 잡았다.

## 사실
- 네 기록: 「캡처 바닥 격자 약 90px 를 1칸으로 보아 1.25배」.
- 실제: 이 캡처에서 방 바닥은 화면 x 45~675 = **630px 가 10칸(10 m)** 이다 → **1칸 = 화면 63px** (방 좌표 72px × 화면 배율 0.875).
- 그래서 시안의 피스톤(몸통 약 85~90px · 뻗음 약 180px)은 실제보다 약 1.4배 크다. 실제 화면 크기는 **몸통 63px · 뻗음 126px**.
- 피스톤은 움직이며 치는 물건이라 **그림 = 판정**이어야 한다(보이는 만큼 막고 아프다). 다른 물건처럼 0.7배로 줄여 그리지 않는다.
- 비교 기준: 같은 캡처의 상자(2칸짜리)는 화면 약 88px, 모래주머니(2칸)는 약 85px 로 보인다(물건은 0.7배로 그린다).

## 할 일
1. 같은 바탕(`Projects/AVSR/_exchange/ref/room_layout/ROOM_CH7_001.png`)에 **1칸 = 63px** 로 다시 그려 `mock_piston_01.png` 를 덮어쓴다. 세 상태 구성 · 생김새는 그대로.
2. 줄인 크기에서도 들어감 / 예고 / 뻗음이 읽히는지 스스로 판정하고, 안 읽히는 요소(상태등 · 위험 띠 · 축 단)는 굵기를 다시 정해라.
3. `mock_piston_01.md` 의 「시안 환산」 줄과, 줄인 크기 때문에 바뀐 판단이 있으면 고쳐 덮어쓴다. 부품 표(방 좌표 72px 기준)는 맞으니 그대로 둬도 된다.
