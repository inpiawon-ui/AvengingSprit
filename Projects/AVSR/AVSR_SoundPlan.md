### 프레임워크 사운드가 못 하는 것 (프레임워크는 수정 금지)

| 한계 | 영향 | 대응 |
|---|---|---|
| `PlayBGM` 은 **파일 전체를 반복**한다. 루프 시작 지점을 모른다 | 인트로가 있는 곡(12곡 중 9곡)이 매 바퀴 인트로부터 다시 나온다 | 게임 쪽에서 **인트로 + 루프 재생기**를 따로 만든다 (3절) |

| 채널 볼륨은 있지만 저장 안 함 | 껐다 켜면 볼륨이 돌아온다 | 설정 화면이 생길 때 PlayerPrefs 로 저장 |

## 2. 에셋 준비

1. **Addressable `sounds` 그룹 생성** — 주소 규칙 `{그룹 폴더}/{파일명}`
   - `Sounds/bgm_01` … `Sounds/bgm_12`, `Sounds/sfx_16` … `Sounds/sfx_38`
   - 라벨 `label_sound`
   - `Samples/` 37개(원작 사운드 CPU 가 조합하는 원재료)는 **등록하지 않는다**(결정 필요 D7)
2. **임포트 설정**

   | 종류 | Load Type | 압축 | 이유 |
   |---|---|---|---|
   | BGM | Compressed In Memory | Vorbis 품질 70 | 인트로+루프를 샘플 단위로 이어 붙이려면 스트리밍보다 메모리 쪽이 안정적이다 |
   | SFX | Decompress On Load | ADPCM | 짧고 자주 난다 — 재생 순간 지연이 없어야 한다 |

   - 원본은 이미 모노라 `Force To Mono` 는 건드리지 않는다
   - Vorbis 로 바꾸면 빌드 용량이 129 MB → 대략 15~25 MB 로 준다(원본 WAV 는 그대로 둔다)

## 3. 코드 구조

### 3.1 모듈 등록

- `GameLauncher.RegisterModules()` 에 `SoundModule` 을 등록한다.
  - ⚠ `SoundModule.Register()` 가 **오브젝트 풀을 즉시 찾는다.** 풀은 `base.RegisterModules()` 에서 자동 등록되므로 순서를 맞춰야 한다(`Assets/Scripts/CLAUDE.md` 경고 그대로)

### 3.2 게임 모듈 `SoundDirector` (새로 만든다 — `Assets/Scripts/Module/Common/Sound/`)

> 규칙대로 **코드 전에 `Assets/Scripts/Module/CLAUDE.md` 에 명세를 먼저 적는다.**

| 역할 | 방법 |
|---|---|
| **BGM 재생 (인트로+루프)** | AudioSource 두 개로 **dspTime 예약 재생**: 1번이 처음부터 재생 → 루프 끝 시각에 2번이 `루프 시작 샘플`부터 이어받고, 이후 두 개가 번갈아 이어받는다. 이음매에서 끊김이 없다 |
| **곡 바꾸기** | 같은 곡이면 **다시 틀지 않는다**(방이 바뀔 때마다 처음부터 나오면 안 된다). 다른 곡이면 0.4초 페이드 |
| **원샷 곡** | `bgm_07`(클리어) · `bgm_10`(실패) · `bgm_11` 은 루프 없이 한 번 |
| **SFX** | 프레임워크 `ISoundManager.Play` 를 쓰되, 앞에서 거른다: 같은 소리 **최소 간격 0.06초**, 같은 소리 **동시 3개까지** |
| **이벤트로 붙인다** | 전투 코드 곳곳에 소리 호출을 흩뿌리지 않고, 이미 있는 게임 이벤트를 구독한다(3.3). 이벤트가 없는 순간만 전투 코드에서 한 줄 부른다 |

### 3.3 곡·효과음 표 `SoundTable` (TableData 에 새로 만든다)

- 칸: `키 · 주소 · 루프 시작 샘플 · 루프 길이 샘플 · 볼륨`
- 루프 지점은 **매니페스트 JSON 에서 에디터 도구로 읽어 넣는다** — 손으로 옮겨 적지 않는다
- 장면 ↔ 곡, 호스트 ↔ 공격음·피격음 대응도 이 표에 둔다 — 코드에 곡 번호를 박지 않는다
