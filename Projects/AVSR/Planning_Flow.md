# 기획 → 디자인 → 클라이언트 플로우 (표준 작업 시스템)

> **역할**: 새 게임을 만들 때 따르는 **표준 진행 순서**. 프로젝트가 바뀌어도 이 플로우 그대로 재사용한다.
> **핵심 원칙**: ① 콘텐츠 구성을 먼저 정한다(씬은 나중). ② 각 단계 끝에 **사용자 승인 게이트**를 둔다.
> ③ 앞 단계가 확정되기 전에 다음 단계로 넘어가지 않는다.

---

## 단계 요약

```
Stage 0.  컨셉(입력)      Game_Concept.md ─ 이미 컨펌된 간략 컨셉
   │
Stage 1.  게임 구성       [ProjCode]_GameComposition.md ─ 필러 · 콘텐츠 · 루프 (씬 무관)
   │    └── 게이트 A: 콘텐츠 구성·루프·기둥 결정 승인
   │
Stage 2.  콘텐츠별 세부    [ProjCode]_Content_[이름].md ─ 콘텐츠마다 1문서
   │    └── 게이트 B: 콘텐츠 단위 승인
   │
Stage 2b. 화면 설계       [ProjCode]_Screen_[이름].md + 박스 목업(HTML/SVG)
   │    ─ 화면 인벤토리 · 네비 플로우 · 화면별 요소 트리(이름·UI타입·anchor·바인딩)
   │    └── 게이트 B2: 화면 레이아웃·요소 승인  (씬 그룹핑은 아직 안 함)
   │
── 기획 종료 / 디자인 시작 ──
   │
Stage 3.  디자인          ① 화면→씬 그룹핑 ② 프리팹 생성(unityMCP/에디터툴) ③ 에셋(ComfyUI)
   │    └── 게이트 C: 씬 구성·프리팹 승인
   │
Stage 4.  클라이언트       프리팹 바인딩 + 기능 구현 (네이밍 규약으로 요소↔이벤트 연결)
```

| 2 콘텐츠별 세부 | `[ProjCode]_Content_[이름].md` | `Projects/[ProjCode]/` | 콘텐츠별: 목적·화면요소·규칙·데이터·연출·의존 | 화면 레이아웃, 프리팹, 코드 |

| 4 클라이언트 | 모듈·스크립트 + 씬 배선 | `Assets/Scripts/` | 기능 구현, 요소↔이벤트 배선, 세이브 | 신규 기획 |

## 게이트 규칙 (사용자 승인)

- **게이트 A** — 게임 구성 확정. "콘텐츠 구성·루프가 이대로 맞다"는 승인. 이후 씬/프리팹/코드의 기준선.
- **게이트 B** — 콘텐츠별 세부 확정. 콘텐츠 **하나씩** 승인 → 승인된 콘텐츠만 디자인·구현으로 내려간다.
- **게이트 C** — 디자인 확정. 씬 구성과 프리팹 목록 승인 → 클라 구현 착수.
- 승인 없이 다음 Stage로 진행하지 않는다. 변경은 해당 Stage 문서를 고치고 게이트를 다시 통과.

## 디자인 파이프라인 & 핸드오프 규약 (Stage 2b → 3 → 4)

화면 설계(2b)가 프리팹·구현으로 결정론적으로 이어지도록 **네이밍 규약**을 접착제로 쓴다.

```
화면 설계(2b)                 디자인(3)                        클라이언트(4)
요소 트리                →   프리팹 생성 + 에셋            →   프리팹 바인딩
─────────                    ─────────                        ─────────
요소 이름                →   GameObject 이름(동일)        →   바인딩 키(동일)
UI 타입(~UI/~Panel/~Popup) →  해당 UI 프리팹 타입           →   UIPanel 등 베이스
바인딩 데이터/이벤트       →   (placeholder)                →   IEventBus 구독/갱신
```

- **요소 이름 = GameObject 이름 = 클라 바인딩 키** (세 곳이 동일해야 자동 연결).
- **UI 타입**은 리포 규약 [`06_ui.md`](../.claude/rules/project/06_ui.md)의 `~UI / ~Panel / ~Popup / SystemPopup`를 그대로 태깅.
- **프리팹 생성**: `unityMCP`(mcp-for-unity) 또는 리포 에디터 툴(CreatePrefabs)로 요소 트리 → GameObject 계층. placeholder 텍스처·아틀라스·Addressable 자동(리포 규약 03/05).
- **비주얼 에셋**: 화면 설계의 Image 요소를 모은 **에셋 매니페스트**(`[ProjCode]_AssetManifest.md`)가 `ComfyUI` 입력이 된다. 파일명=요소명 규약으로 생성 스프라이트를 프리팹 슬롯에 자동 적용.
- **이벤트**: 각 콘텐츠 세부 기획(§6)에 이미 정의된 발행/구독 이벤트를 클라가 요소에 연결.
- **실행 제약**: unityMCP는 Unity 에디터 실행, ComfyUI는 NAS 접근이 필요. 헤드리스 세션에선 설계·요소 트리·박스 목업까지만.

## 기존 A~E 템플릿 체계와의 관계

이 플로우는 기존 [`00_Master_Index.md`](00_Master_Index.md)의 A~E(가이드/파트/계획서/세부설계/실무) 체계와 **충돌하지 않는다**.

- Stage 1(게임 구성)은 A~E의 **C(계획서) 앞단 진입 산출물**이다 — 콘텐츠 구성·루프를 먼저 확정해 C/GD 세부설계의 입력이 된다.
- Stage 2(콘텐츠별 세부)는 파트 문서 중 **GD(기획, `02_GameDesign.md`)** 의 코어루프·시스템 슬라이스에 대응한다.
- ART/CL/SV/SND 등 파트별 심화가 필요해지면 그 시점에 A~E의 D(세부설계)로 확장한다.
- 즉 **가볍게 시작(게임 구성 → 콘텐츠별) → 필요 시 A~E로 심화**하는 관계다.
