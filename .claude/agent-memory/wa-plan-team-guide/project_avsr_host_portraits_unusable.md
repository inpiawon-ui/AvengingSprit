`Projects/AVSR/Reference/Hosts/` 에 **정본 12종 `{hostKey}.png` (91×84)** + 코스튬 변형 3종
(`rambo_laser`·`wizard_green`·`ninja_red`) + `x3/*_x3.png` 확대본이 추출되어 있다 (2026-08-07 팀장 작업).
`host_select.jpeg` 그리드 원점 `(16.7, 236.7)` · 셀 피치 `106.7×125.0` 에서 잘라냈다.
**15칸 = 정본 12 + 색상 변형 3**이 육안 확정됐다 — 확정 #10(15→12)의 실증 근거.

> 이전 버전 메모는 "빈 그라데이션이라 사용 불가"였다. **그 판정은 낡았다** — 재추출로 해소됐다.

**Why:** 이 12종은 **원작 IP 캐릭터**다. GPT는 생성할 때마다 얼굴이 미세하게 달라지므로
재생성하면 "목업 100% 재현"(확정 #5)이 깨진다. 크롭은 정의상 목업과 100% 일치하고 문제는 해상도뿐이다.
같은 이유로 `logolockup`(계약 IP 로고)·`ghostavatar`(원작 마스코트)·`bossportrait`도 CROP으로 잡았다.

**How to apply:** AVSR 에셋 생성 방식을 정할 때 `GPT` / `CROP` / `CROP+GPT` 3분류를 쓴다.
**재생성하면 안 되는 것(IP 로고·원작 캐릭터 얼굴)만 CROP**, 크롭 해상도가 목표에 미달하고 얼굴 식별이
불필요한 것은 `CROP+GPT`, 나머지는 `GPT`.
⚠️ **핵심 원칙 — 목표 px를 먼저 정하고 크롭을 늘리지 않는다. 크롭 실측치가 최종 규격을 결정하게 한다.**
(예: 로고 크롭이 `194×102`로 나왔으므로 타이틀 로고를 480 슬롯에 맞추는 대신 ×3 = `582×306`으로 정했다.)
그래야 확정 #16(정수 배율)을 위반하지 않는다. 이 원칙 때문에 화면 설계서 6개 요소의 크기를 역으로 갱신했다.
목업이 JPEG이므로 크롭에는 **색 수 양자화(16색 이하) 클린업**이 필요하다.
