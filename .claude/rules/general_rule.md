# 일반 코딩 규칙

LLM의 흔한 코딩 실수를 줄이기 위한 행동 지침이다.

**트레이드오프:** 이 지침은 속도보다 신중함을 우선시한다. 단순한 작업에는 판단을 활용한다.

## 1. 코딩 전에 먼저 생각하라

**가정하지 말고, 혼란을 숨기지 마라. 트레이드오프를 드러내라.**

구현 전에:
- 가정을 명시적으로 밝혀라. 불확실하면 물어라.
- 여러 해석이 가능하면 제시하라 — 조용히 하나를 고르지 마라.
- 더 단순한 접근이 있으면 말하라. 필요하면 반대 의견을 내라.
- 불명확한 부분이 있으면 멈춰라. 무엇이 헷갈리는지 말하고 물어라.

## 2. 단순성 우선

**문제를 해결하는 최소한의 코드. 추측성 코드는 없다.**

- 요청한 것 이상의 기능 금지.
- 단일 사용 코드에 추상화 금지.
- 요청하지 않은 "유연성"이나 "설정 가능성" 금지.
- 불가능한 시나리오에 대한 오류 처리 금지.
- 200줄로 쓰고 50줄로 줄일 수 있다면, 다시 작성하라.

스스로 질문하라: "시니어 엔지니어가 이게 과하다고 할까?" 그렇다면 단순화하라.

## 3. 외과적 변경

**반드시 필요한 것만 건드려라. 자신이 만든 문제만 정리하라.**

기존 코드를 편집할 때:
- 인접한 코드, 주석, 형식을 "개선"하지 마라.
- 망가지지 않은 것을 리팩터링하지 마라.
- 다르게 작성했겠지만, 기존 스타일을 따르라.
- 관련 없는 죽은 코드를 발견하면 언급하라 — 삭제하지 마라.

변경으로 인해 고아가 된 경우:
- 자신의 변경으로 인해 미사용이 된 import·변수·함수는 제거하라.
- 기존에 존재했던 죽은 코드는 요청받지 않으면 제거하지 마라.

기준: 변경된 모든 줄이 사용자의 요청으로 직접 추적 가능해야 한다.

## 4. 목표 중심 실행

**성공 기준을 정의하라. 검증될 때까지 반복하라.**

작업을 검증 가능한 목표로 변환하라:
- "유효성 검사 추가" → "유효하지 않은 입력에 대한 테스트 작성 후 통과시키기"
- "버그 수정" → "버그를 재현하는 테스트 작성 후 통과시키기"
- "X 리팩터링" → "리팩터링 전후 테스트 통과 확인"

다단계 작업에는 간략한 계획을 명시하라:
```
1. [단계] → 검증: [확인 사항]
2. [단계] → 검증: [확인 사항]
3. [단계] → 검증: [확인 사항]
```

명확한 성공 기준은 독립적으로 반복 작업을 가능하게 한다. 모호한 기준("잘 작동하게 해줘")은 끊임없는 확인을 요구한다.

**이 지침이 효과적일 때:** diff에 불필요한 변경이 줄어들고, 과도한 복잡성으로 인한 재작성이 줄어들며, 실수 후가 아닌 구현 전에 명확한 질문이 나온다.
