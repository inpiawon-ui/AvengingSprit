# 이펙트(FX) 규칙

> PD 결정 2026-10-08. 결과창 상자 아우라를 그림으로 받아 딱딱한 별 덩어리가 된 뒤 정했다
> 「왜 이펙트를 꼭 이미지로 픽셀 느낌을 살리려 하냐, 파티클로 퀄 좋게 뽑으면 안 되냐」.

## 진행 절차는 스킬 `fx-art-pipeline` (`.claude/skills/fx-art-pipeline/SKILL.md`)

> PD 2026-10-09 — 결과창에서 **코덱스 자유 시안**이 한 번에 통과했다. 아트 목표는 코덱스 자유 시안으로 먼저 잡고, PD 가 고른 시안이 정답이다.
> 순서: 지금 모습 캡처 → 연출 가이드(강약) → 코덱스 자유 시안(+가이드 시안) → PD 선택 → 그 화풍으로 부품 발주 → 게임 반영 → 시안과 나란히 검수.

## 0. 기준은 「어울리는가」

> PD 2026-10-08 「모든 게 다 파티클로 한다고 이뻐지는 건 아니야. 픽셀 게임이라 픽셀로 표현해야 될 건 이미지로 해도 되고, 뭐든 어울리게 해야 돼」.

- 이 게임은 **도트 픽셀 게임**이다. 아래 1절 표는 출발점일 뿐, 최종 판단은 **화면에 어울리는가**다.
- 도트로 보여야 맛이 나는 것(불꽃 모양 · 기포 · 금화 · 문양 · 도트 연기 등)은 **픽셀 그림이 맞을 때가 많다** — 그림으로 해도 된다.
- 파티클을 쓸 때도 **입자는 도트 질감**(픽셀 그림 입자 · 점 필터)으로 맞춘다. 매끈한 고해상도 빛이 도트 그림 위에 둥둥 떠 보이면 실패다.
  부드러운 빛 셰이더 번짐은 **받침 · 배경 쪽에 은은하게**만 쓴다.
- 애매하면 그림안 · 파티클안을 같은 화면에 나란히 GIF 로 만들어 비교하고 고른다(코덱스 의견 + PD 확인).

## 1. 무엇으로 만드나 (출발점 — 최종은 고른 시안의 화풍)

> 2026-10-09 보충: 결과창에서 빛 셰이더로 만든 매끈한 번짐 · 빛살은 도트 그림과 따로 놀았고, 코덱스의 도트 빛살 · 반짝 별 시안이 이겼다.
> **시안 화풍이 도트 빛이면 빛도 그림 프레임(검은 바탕, 가산)으로 받는다.** 아래 표는 시안이 없을 때의 출발점이다.

| 이펙트 성격 | 만드는 방식 | 예 |
|---|---|---|
| **형태 없이 퍼지는 빛 · 입자** | **파티클 시스템 + 빛 셰이더(가산)** | 아우라 · 반짝임 · 빛 번짐 · 빛 알갱이 · 불씨 · 연기 · 먼지 · 속도선 · 충격파 고리 |
| **형태가 있는 그림** | **프레임 그림 발주**(코덱스) | 저주 덩굴 · 쇠사슬 · 카드 흡수 문양 · 하트 · 화살표 · 글자 모양 빛 |
| 둘이 섞인 것 | 형태는 그림, 둘레 빛은 파티클로 얹는다 | 카드가 몸에 깃듦(문양 그림 + 빛 알갱이 파티클) |

- 파티클이 쓰는 **입자 텍스처**(점 · 별 · 연기 한 장)는 발주한 그림이나 기존 `Assets/BaseResource/ParticleFx/` 를 쓴다.
  도형 스크립트(`PIL.ImageDraw`)로 찍지 않는다.
- 파티클은 **움직임 · 수 · 수명 · 크기 곡선 · 색 곡선**으로 예쁘게 만든다 — 이게 내 몫이다.
  인게임 파티클은 `Assets/Scripts/Module/InGame/ParticleFxPool.cs` 를 먼저 본다.
- 빛을 그림 시트(분홍 바탕 → 뚫기)로 받으면 부드러운 번짐이 사라지고 딱딱한 모양만 남는다. **빛은 그림으로 받지 않는다.**

## 2. 그림에 빛을 굽지 않는다

- 아이템 · 상자 · 금화 더미 같은 **물건 그림은 빛 · 아우라 · 반짝이 없이** 받는다. 빛은 이펙트로 따로 낸다.
  > 결과창 금화 더미 뒤 주황 빛 · 상자 둘레 아우라가 그림에 박혀 있었다 — PD 「원래 이미지가 아니라 이펙트로 표현해야 되는 거야」.
- 이미 빛이 박힌 그림이 있으면 **빛 뗀 그림을 발주**해 갈아 끼운다(원본은 지우지 않는다).

## 3. 연출에는 이유와 순서가 있어야 한다

- **이유 없는 빛 금지.** 「무엇을 얻었나 · 무엇이 일어났나」가 읽히지 않으면 빼는 것이 낫다. 어설픈 효과는 넣지 않는다.
- **방향이 이야기다.** 산다 = 돈(HUD) → 물건 → 캐릭터 → 효과. 고른다 → 고른 것에 포커스 → 창이 닫힘 → 캐릭터에 효과.
- 보상은 **창을 닫고 캐릭터 위에서** 잠깐 멈춰 보여 준다(무엇을 · 얼마나).
- 팝업 장식은 **은은하게 계속 도는 것**(숨쉬기 · 흐름 · 반짝임 루프). 열 때 한 번 「팍」 터지는 것, 테두리 전부 금빛은 금지.
- 이펙트는 **게임 정보(글자 · 숫자 · 아이콘)를 가리지 않는다.** 칸에 붙는 빛은 칸 그림 위 · 글자 아래.
- 물건 뒤 · 앞 깊이를 정한다. 애매하게 반쯤 덮이면 물건 **뒤**로 보낸다.
- 등장 연출은 곡선(OutBack · OutCubic · OutBounce 등, `Assets/Scripts/Module/Common/UI/Ease.cs`)을 쓴다. 숫자 배율(1.2 → 1)을 그대로 박지 않는다.

## 4. 코덱스와 같이 정한다

> 2026-10-09: 코덱스에게는 항상 공용 브리프 `Projects/AVSR/_exchange/codex_brief_fx.md`(우리가 정한 방향)를 먼저 읽게 한다.
> PD 와 새로 정한 것은 브리프에 먼저 적는다 — 광원 얘기를 빼먹어 코덱스가 툰 · 도트로만 그렸다.

> PD 2026-10-08 「코덱스랑 같이 정할 것 — 리소스는 코덱스도 잘 잡는 것 같아서 같이 진행하는 느낌이 좋을 것 같아」.

**리소스 · 이펙트는 혼자 정하지 않는다.** 새 리소스(그림) · 새 이펙트 · 기존 것을 크게 바꿀 때는 만들기 전에 코덱스와 같이 정한다.

- **같이 정할 것**: 방식(파티클 / 그림 / 섞음) · 연출 순서(무엇이 언제 어디서 어디로) · 크기 · 색 · 깊이(앞 / 뒤) · 발주 사양.
- **방법**: 상의서(`Projects/AVSR/_exchange/consult_*.md` + `.ps1`)에 PD 피드백 원문 · 지금 화면 캡처 경로 · 내 안을 적어 코덱스에 묻고,
  답을 받아 **합친 안**을 정한다. 상의서 · 답 · 합친 안은 `_exchange/` 에 남긴다(무엇을 왜 그렇게 정했는지 근거).
- **받은 리소스 검수도 같이 본다** — 넣기 전 납품 그림 · 미리보기 GIF 를 코덱스에게 보여 주고 의견을 받는다.
- 코덱스 사용은 ChatGPT 로그인만(API 키 금지, `$env:OPENAI_API_KEY = $null`). 같은 주제를 여러 회차 핑퐁하지 않는다 — 상의 1회 · 검수 1회가 기본.
- 최종 구현 · 게임 반영 · 검증 · PD 보고는 내가 한다. 코덱스 의견과 내 판단이 다르면 둘 다 PD 에게 보여 준다.

## 5. 진행 순서 — 숫자보다 그림이 먼저

> PD 2026-10-08 「퀄 자체가 엉망 · 약하게 할 때는 약하게, 힘줄 때는 힘을 줘야지 · 연출 가이드는?」 —
> 결과창 빛을 그림 목표 없이 숫자(알파 · 크기)만 코덱스와 주고받아 정했다가, 둘 다 「최대한 약하게」로 쏠려 「더미로 나온 느낌」이 났다.

0. **연출 가이드부터.** 박자표(무엇이 · 언제 · 얼마나 세게 · 몇 초)를 쓴다. **강약을 반드시 적는다** — 힘줄 박자(착지 · 완성 · 획득 순간)와
   쉬는 박자(머묾)를 나누고, 힘줄 박자는 확실히 세게 한다. 기준 그림(예: 예전 그림에 박혀 있던 빛)이 있으면 **그 느낌이 목표**다 — 지우는 쪽으로 가지 않는다.
   상의서에 PD 의 싫어함만 앞세우지 않는다(코덱스가 「최소」로 쏠린다). 목표 모습을 먼저 적는다.
0-1. **시안(완성 화면 몇 컷)을 코덱스와 만들어 PD 확인** — 통과 전에는 게임에 넣지 않는다. 통과한 시안이 정답이고, 넣은 뒤 나란히 재서 맞춘다.
1. **코덱스와 같이** 방식 · 순서 · 사양을 정한다(4절).
2. 그림이 필요하면 발주 → 받은 것을 먼저 검수(스크립트로 때웠는지 · 빛이 딱딱한지) — 코덱스 의견도 받는다.
3. **게임에 넣기 전에 움직이는 GIF**(실제 크기 · 실제 배경 · 실제 색)로 PD 확인. 정지 스샷 금지.
4. 넣은 뒤 **게임에서 녹화**해 프레임 단위로 확인하고 GIF + 파일 경로로 보고한다.
