# 자기 점검 프로세스

모든 작업이 끝나면 반드시 다음 순서로 점검하라:

1. **결과 검증** — 실제로 실행해서 의도한 대로 동작하는지 확인
2. **엣지 케이스** — 예외 상황이 처리되지 않은 부분이 있는지 확인
3. **개선 여부 판단** — 문제가 있으면 그 문제가 발생하게 된 근본적인 원인을 분석해서 수정 후 1번부터 다시 반복
4. **완료 조건** — 연속 점검을 통과했을 때만 완료로 선언

---

## 못 잰 것은 통과가 아니다 (2026-10-22)

결과는 **통과 / 우려 / 반려 / 미검** 중 하나로 말한다. 볼 것 · 잴 것이 없어 판단을 못 했으면 **미검**이다 — 「문제 없음」이 아니다.

- 점검이 아무것도 못 찾았을 때, **찾을 대상이 있었는지**부터 본다(파일 0개를 훑고 「경고 없음」이라 하지 않는다).
- 시험 조건이 안 맞아 효과가 아예 안 났으면 미검이다 — 몸 조건이 달라 카드가 꺼진 채 찍힘 · 체력이 문턱 위라 방벽이 안 섬(2026-10-21 카드 녹화).
- 보이는 것을 바꾼 일은 게임에서 실제로 보고(녹화 · 캡처) 남긴 뒤에만 통과다. 화면 · 움직임 증거가 없으면 미검이다.
- 미검을 보고할 때는 무엇이 없어서인지 · 언제 채울지 같이 적는다.

## Unity C# 코드 변경 시 추가 점검

1번 "결과 검증"은 Unity 에디터에서 컴파일 오류가 없음을 포함한다.

- **에디터 실행 가능**: Unity Editor Console에서 컴파일 오류 0건 확인 후 완료 선언
- **에디터 실행 불가**: "컴파일 미확인" 상태를 명시하고, 사용자에게 직접 확인을 요청한 뒤 완료 선언

**컴파일 확인 없이 완료를 선언하지 않는다.**
정적 분석(네임스페이스·using·인터페이스 시그니처 대조)은 보조 수단이며, 실제 컴파일을 대체하지 않는다.
