# 시안 → 게임 UI 적용

시안을 «비슷하게» 가 아니라 **같게** 옮기고, 사람이 눈으로 찾던 깨짐(잘림·겹침·화면 밖·글자 가림·찌그러짐)을 **하네스가 먼저 찾게** 하는 흐름이다.
하네스는 Screen Space - Overlay 캔버스만 잰다 — Camera·World Space 화면은 캡처를 눈으로 본다. 하네스에 맞추려고 기존 UI 의 렌더 모드를 바꾸지 않는다.
로드랜드(RDL) 로비를 이 방식으로 만들며 정리했다 — 게임과 무관한 부분만 여기 적는다.

> **이 프로젝트 고유 값(시안 폴더·해상도 이름·메뉴·취향)은 같은 폴더의 `project.md` 에 있다. 있으면 먼저 읽는다.**
> 하네스 사용법 정본은 하네스 폴더의 `README.md`(규칙표 C1~C6·R1~R4, 예외 문법, 한계)다 — 여기서 다시 적지 않는다.

## 0. 착수 전 확인

- 하네스가 있는가: `UiHarnessRunner.cs`·`IUiHarnessProfile` 을 찾는다. 없으면 적용 안내서(`Tools/ui-mockup-kit/APPLY.md` — 원본 리포)를 따라 먼저 들인다.
- 이 게임 프로필(`IUiHarnessProfile` 구현)과 메뉴가 있는가. Game 뷰에 해상도 크기가 등록돼 있는가(이름이 프로필 `Resolutions` 와 같아야 한다).
- 시안 이미지가 리포에 있는가(프로필 `MockFolder`). 없으면 받아서 넣는다 — 시안 없이 «감으로» 배치하지 않는다.
- **에디터가 플레이 중이면 컴파일·재임포트를 걸지 않는다.** 사용자가 플레이 중일 수 있다. 하네스는 끝나도 플레이를 켜 둔다 — 내가 켠 것이면 끄고 컴파일한다.

## 1. 시안을 숫자로 바꾼다

- 시안 해상도(예: 1920×1080)를 기준 판으로 정하고, 부품마다 **시안 픽셀 상자**(왼·위·오른·아래)를 잰다. 눈대중 금지 — Pillow 로 잘라 경계를 찾는다.
- 글자는 «칸»이 아니라 **잉크 상자**(실제 글자 획이 차지한 영역)를 잰다. 글꼴마다 위아래 여백이 달라 칸 기준으로 맞추면 위아래로 밀린다.
- 코드에는 상자를 상수로 둔다(예: `MockBox(x0,y0,x1,y1)`) — 부모 기준점과 함께 «시안 좌표 → 앵커 위치» 로 바꾸는 도우미 하나로만 배치한다. 숫자를 손으로 환산해 흩뿌리지 않는다.
- 같은 부품이 반복되면(줄·칸) 첫 상자 + 간격으로 만든다.

## 2. 같게 만든다 — 글자까지

- **글자 크기는 줄 폭으로 맞춘다** — 시안 잉크 폭 ÷ 지금 잉크 폭으로 크기를 고친다. 글꼴이 시안보다 넓거나 높으면 칸 비율(가로·세로 배율)로 맞춘다.
- 색·외곽선 두께·외곽선 색·그림자·굵기까지 시안 값을 뽑아 쓴다. 너무 진한 검정·뭉개진 외곽선은 버그로 보인다.
- 긴 번역 문구는 자동 축소(최소 크기)와 여백으로 받는다 — 하네스 C4 경고(«하한에 닿음»)가 뜨면 여유가 없다는 뜻이다.
- **없는 그림은 근사하지 말고 요청한다**(색 판으로 임시로 세우되 «그림 필요» 로 보고). 늘려 쓰는 판은 9분할(Sliced) — R2.
- 시안에 없는 장식을 더하지 않는다. 연출(빛·파티클)은 하네스 예외로 빼되 «경로 + 이유» 로 좁게.

## 3. 해상도 — 설계 판 하나 + 비율별 배치

- 화면은 **설계 판(시안 크기)을 창에 맞춰 같은 배율로 줄이는 방식**(min-fit)이 기본이다. 해상도마다 따로 좌표를 짜지 않는다.
- 배경은 화면 전체를 덮고(cover) 검은 여백을 남기지 않는다. 내용물만 해상도에 맞춘다.
- 세로가 긴 화면(4:3 태블릿)은 가로가 먼저 닿아 위아래가 빈다 → **세로 배치를 따로 등록**한다:
  큰 묶음을 판 크기 «틀»로 한 번 감싸 그 틀만 옮기고 키운다(묶음 자신의 자리는 그대로 — 열림 연출이 기억한 자리가 깨지지 않는다).
  판 자체를 세로로 늘려야 하면 자리·크기를 «세로 배치 값»으로 등록해 휴대폰 배치에서 되돌린다. 가로가 꽉 찬 화면은 배율로는 거의 못 키운다 — 세로로 늘리는 안을 보인다.
- 최소 세 비율로 본다: 16:9 · 20:9(긴 휴대폰) · 4:3(태블릿). 노치·안전 영역이 있으면 그것도.

## 4. 하네스로 잰다

- 화면(상태)을 만들거나 바꾸면 **프로필에 시나리오를 더한다**: `Enter`(시작 화면에서 그 상태까지 **실제 클릭**으로 간다 — 가려져 있으면 실패한다) ·
  `Expect`(도달했는지, 문제 없으면 null) · `Settle`(해상도를 바꾼 뒤 다시 세울 것 — 누름 유지 등) · `Mock`(비교할 시안 이름).
  누른 상태·탭·언어(긴 번역)·모달처럼 **지적이 나왔던 상태는 다 시나리오로 남긴다** — 다음 변경이 다시 깨면 하네스가 잡는다.
- 규칙은 프로필 `Rules` 에: 판 안에 있어야 할 것은 `Contain`, 모달은 `Modal`, 겹쳐 쌓는 화면은 `ExclusiveChildren`, 의도된 예외는 `AllowRule(규칙, 경로, 이유)`.
  예외는 좁게 — 쓰이지 않은 예외는 리포트에 따로 뜨니 지운다.
- 실행 → `Temp/UiHarness/<이름>_<시각>/report.md` 맨 위 **«기계 검사 통과»** 줄이 합격선이다(실패 0 · 도달 실패 0 · 실행 오류 없음 · 샷 다 있음).
  실패 개수만 보고 통과로 판단하지 않는다. PNG 가 «상태 수 × 해상도 수» 만큼 있고 각 크기가 그 해상도와 같은지도 본다. 통과할 때까지 고친다.
  경고는 읽고 판단한다(R3 확대·C4 하한·C1? 추정 판).
- 오탐이면 예외를 넣기 전에 **정말 오탐인지 캡처로 확인**한다. 실제로 잘린 글자를 예외로 덮은 적이 있다.

## 5. 눈으로 대조한다 — 하네스 합격 ≠ 시안 일치

- `contact_sheet.py <결과 폴더>` 로 «시안 | 해상도별 게임» 비교판을 만든다. 위반 상자(빨강 실패·주황 경고)가 그려진다.
- 바뀐 부분은 확대해서(잘라서) 시안과 나란히 본다 — 글자 위치·크기·색, 버튼 안 글자 중심, 외곽선, 간격.
- 애니메이션이 있는 화면은 연출이 끝난 프레임을 본다(찍는 순간이 연출 중이면 판단하지 않는다).
- 사용자에게는 **세 해상도 캡처를 함께** 보여 준다.

## 6. 교차 검수 후 보고

- 구현 전 의견, 구현 후 검수를 다른 검토자(Codex 등)와 주고받는다 — 캡처·리포트·diff 를 넘기고 PASS/FIX 로 받는다. 마지막 수정까지 통과한 뒤 보고한다.
- 보고에는 **무엇을 확인했고 무엇은 못 했는지**를 적는다(예: «4:3 은 캡처로만 봤다 · 실기기 미확인»).

## 7. 완료 조건

1. 컴파일 오류·경고 0 (실제 컴파일로 — 콘솔이 비어도 DLL 시각이 옛것이면 컴파일되지 않은 것이다)
2. 하네스 실패 0, 경고는 판단 근거와 함께
3. 바뀐 화면의 세 해상도 캡처를 눈으로 대조함(시안과 나란히)
4. 관련 자동 테스트 통과 · 회귀 시험(버그를 고쳤다면 고치기 전 재현 → 고친 뒤 통과)
5. 교차 검수 통과

## 자주 밟은 함정

| 증상 | 원인 · 처방 |
|---|---|
| 글자가 위나 아래로 몇 px 밀린다 | 칸 기준으로 맞췄다 — 잉크 상자 기준으로 |
| 고른 뒤 아이콘이 글자 위로 겹친다 | 연출이 «지을 때 기억한 자리»로 되돌림 — 연출은 움직일 축(예: 세로)만 쓴다 |
| 4:3 에서 전부 작다 | 가로가 먼저 닿는다 — 세로 배치(틀 이동·판 세로 늘림)를 따로 둔다 |
| 화면 속 그림의 위아래가 잘린다 | 덮기(Envelope)로 맞췄다 — 핵심 그림은 안에 다 들어가게(Fit), 남는 곳은 이어 그린 배경으로 |
| 하네스는 통과인데 버튼이 안 눌린다 | 하네스는 포인터 이벤트를 직접 보낸다 — 입력 모듈(Input System 등)까지는 재지 않는다. 실제 입력은 플레이로 눌러 본다 |
| 버튼이 다른 판에 가렸는데 하네스가 못 잡았다 | C6 은 «TMP 글자가 뒤 그림(Image)에 가리는지»만 근사로 본다(시나리오에서 클릭한 대상만 레이캐스트 가림도 본다) — 버튼 가림 전체를 보장하지 않으니 캡처로 본다 |
| 같은 글자가 두 겹 겹쳐 C5 실패 | 테 장식(같은 글자 두 겹)이면 경로를 좁혀 `AllowRule("C5", …)` |
| 글자가 두부(□)로 나온다 | 정적 글꼴 아틀라스에 그 글자가 없다 — 번역에 글자를 더했으면 아틀라스를 다시 굽는다 |
| 머티리얼이 늘어난다 | 글꼴·외곽선을 바꿀 때 복제 머티리얼을 버리지 않았다 — 이전 복제본을 지운다 |
