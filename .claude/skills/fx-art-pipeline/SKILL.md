# 이펙트 · 아트 제작 순서 (fx-art-pipeline)

> PD 2026-10-09 「코덱스 자유 시안처럼 나올 수 있게 하네스 · 스킬 · 메모리에 저장해서, 다음부터는 최대한 핑퐁이 일어나지 않게」.
> 결과창 금화 · 상자 빛을 숫자(알파 · 크기)만 코덱스와 주고받다 「퀄 엉망」을 몇 번 받았다.
> **코덱스 자유 시안**(코덱스가 아트 디렉터로 그린 완성 화면)을 먼저 받아 보여 주자 PD 가 한 번에 골랐다. 이 순서를 따른다.
> 규칙 본문: `.claude/rules/project/08_fx.md` · 역할: 코덱스 = 아트(시안 · 부품 그림) / Claude = 가이드 · 발주 · 게임 반영 · 타이밍 · 검증 · 보고.

## 코덱스에게는 항상 브리프를 같이 준다
- `Projects/AVSR/_exchange/codex_brief_fx.md` — 우리가 정한 방향(빛 = 도트 모양 + 셰이더 광원 · 파티클, 강약, 기승전결, PD 원문 금지 사항, 통과 기준 그림).
- 시안 · 부품 · 상의 발주문 첫 줄에 「먼저 이 브리프를 읽는다」를 넣는다(`order_codex_mock.py` · `order_result_fx_parts.py` 는 이미 넣었다).
- PD 와 새로 정한 것이 생기면 **브리프에 먼저 적는다** — 그래야 코덱스가 처음부터 같은 생각으로 그린다
  (2026-10-09: 광원 얘기를 안 해서 코덱스가 툰 · 도트로만 그렸다).

## 0. 시작 전
- 유니티는 다른 세션과 같이 쓴다 — 쓰기 전에 알리고(필요하면 PD 확인), 끝나면 「다 썼다」.
- 세이브(`%LOCALAPPDATA%Low\WA Studio\AVENGING SPIRIT RE_BORN\SaveData`)는 시험 전에 백업, 끝나면 되돌린다. 지우지 않는다.

## 1. 지금 모습 캡처 (바탕)
- 게임에서 그 장면을 녹화한다 — **힘주는 순간**(완성 · 착지 · 획득)과 **머무는 장면** 두 컷.
- 해당 칸만 잘라 2배로 키워 `Projects/AVSR/_exchange/ref/<주제>_mock/base_*.png` 에 둔다(글자가 읽히는 크기).

## 2. 연출 가이드 (짧게 · 목표 먼저)
`Projects/AVSR/_exchange/guide_<주제>.md`
- **목표 모습**을 먼저 쓴다 — 기준 그림(예전 그림에 박혀 있던 빛, 승인 시안)이 있으면 그 느낌이 목표. 「떼라」는 「없애라」가 아니라 「더 멋지게 살려라」.
- **박자표**: 시각 · 박자 · **강약(강 / 중 / 약)** · 무엇이 보이나. 힘줄 박자(완성 · 착지 · 획득 순간)는 확실히 세게, 머묾은 은은하게.
- PD 원문을 그대로 옮긴다. 금지 사항은 맨 뒤에 짧게(앞세우면 코덱스가 「최소」로 쏠린다).

## 3. 코덱스 시안 (병렬, 한 장씩)
```
python Projects/AVSR/Tools/order_codex_mock.py <주제> <바탕캡처> --ref <기준그림> --pd "<PD 원문>" [--guide <가이드.md>]
powershell -File Projects/AVSR/_exchange/run_mock_<주제>.ps1
```
- **자유 시안**(필수): 「네가 아트 디렉터라면 어떻게 꾸미겠나」 — 힘주는 순간 · 머무는 장면 2컷. 이게 보통 정답이 된다.
- **가이드 시안**(선택): 박자표대로 2컷.
- 납품: `Projects/AVSR/_exchange/in/mock_<주제>_*.png`

## 4. PD 선택
- 비교 시트 한 장(열 = 자유 시안 · 가이드 시안 · 필요하면 지금 화면, 행 = 힘주는 순간 · 머무는 장면)을 만들어 보여 준다 + 파일 경로.
- **같은 매체끼리 비교한다** — 멈춘 그림 시안과 움직이는 게임 녹화를 한 줄에 섞으면 공정하지 않다(2026-10-09 결과창:
  코덱스 그림 시안을 골랐다가 「툰 느낌만 있고 파티클 · 셰이더 느낌이 없다, 게임 녹화의 광원은 괜찮았다」로 뒤집혔다).
- **층별로 고르게 한다** — 「모양(빛살 · 반짝 별 · 화풍)」과 「광원 느낌(번짐 · 블룸 · 입자 움직임)」을 따로 묻는다.
  보통 답은 섞인다: 모양은 코덱스 그림, 광원은 빛 셰이더 · 파티클.
- 내 판단(어느 쪽이 왜 나은지)을 한 줄로 붙인다. **고른 시안 = 게임 연출의 정답.** 통과 전에는 게임에 넣지 않는다.

## 5. 부품 발주 (고른 시안이 앵커)
- 시안을 크롭해 **앵커로 경로를 박는다**. 「비슷한 것」을 말로 대신하지 않는다.
- 물건 그림은 **빛 없이 깨끗하게**(빛은 이펙트로 따로).
- 이펙트 그림:
  - **머묾 반복** 8장(끊김 없이 이어지게), **힘주는 순간 터짐** 6~8장
  - 빛 · 빛살 · 반짝 별 = **검은 바탕**(가산으로 그린다 — 분홍 바탕을 뚫으면 부드러운 빛이 사라진다)
  - 형태 있는 것 = 분홍 바탕 → 뚫기
- 도트 게임이라 빛의 **모양**(빛살 · 반짝 별)은 도트 화풍 그림 프레임이 어울린다. 그러나 그림만 쓰면 툰 느낌만 남는다 —
  **광원 느낌**은 빛 셰이더 번짐(맨 뒤, 힘줄 박자에 확 밝아졌다 숨쉬기) + 파티클 빛 알갱이(앞)로 겹친다. 층: 셰이더 번짐 → 도트 빛살 → 반짝 별 · 파티클.
- 한 장씩 발주, 받으면 먼저 검수(스크립트로 때웠는지 · 지시(십자 금지 등)를 어겼는지 · 시안과 화풍이 같은지).

## 6. 게임 반영
- 박자표대로 타이밍 · 강약 · 깊이(물건 뒤 / 앞) · 글자 안 가리기.
- 곡선은 `Assets/Scripts/Module/Common/UI/Ease.cs`.

## 7. 검수 → 보고
- 게임 녹화 → **시안과 같은 크기로 나란히** 비교 시트 + 움직이는 GIF.
- 넣기 전 · 후 한 번씩 코덱스 의견(검수 1회). 같은 주제 여러 회차 핑퐁 금지.
- PD 보고: GIF + 비교 시트 + 파일 경로 + 내가 보기에 아직 다른 점.

- Claude 가 셰이더 · 도형으로 시안 대신 그리기
- 상의서에 금지만 나열하기
- 물건 밑에 단색 실루엣 판(그림자처럼 보임)
