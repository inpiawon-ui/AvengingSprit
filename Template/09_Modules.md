## 모듈 상세 — MOD-AUTH: 인증 / 계정

**재사용 등급**: ⭐⭐⭐ | **의존 파트**: CL + SV

### 제공 기능
- 소셜 로그인 (Google / Apple / Facebook)
- 게스트 로그인
- JWT 기반 인증 (Access / Refresh Token)
- 계정 연동 (게스트 → 소셜)
- 디바이스 검증

### 주요 API

| API ID | 엔드포인트 | 설명 |
|--------|----------|------|
| API_AUTH_001 | POST /api/v1/auth/login | 소셜 로그인 |
| API_AUTH_002 | POST /api/v1/auth/guest | 게스트 로그인 |
| API_AUTH_003 | POST /api/v1/auth/refresh | 토큰 갱신 |
| API_AUTH_004 | POST /api/v1/auth/logout | 로그아웃 |
| API_AUTH_005 | POST /api/v1/auth/link | 계정 연동 |

### 알려진 제약사항
- Apple 로그인은 iOS 13+ 필수
- Refresh Token은 Redis에 저장 (서버 재시작 시 유지)

### 주요 API

| API ID | 엔드포인트 | 설명 |
|--------|----------|------|
| API_IAP_001 | POST /api/v1/shop/purchase | 구매 요청 + 영수증 검증 |
| API_IAP_002 | GET /api/v1/shop/history | 구매 이력 조회 |
| API_IAP_003 | POST /api/v1/shop/restore | 구독 복원 |

### DB 테이블

| 테이블명 | 주요 컬럼 | 설명 |
|---------|---------|------|
| `purchase_history` | user_id, product_id, amount, platform, receipt, created_at | 결제 내역 (삭제 금지) |

### 알려진 제약사항
- 영수증 검증은 반드시 **서버에서** 처리 (클라 검증 금지)
- 결제 이력 7년 보관 의무

### 제공 기능
- 레이팅 기반 매칭 (ELO / MMR)
- 빠른 매칭 (최대 대기 시간 `[N]초`)

### 매칭 로직

```
1. 매칭 큐 진입
2. 유사 MMR 범위(±[N]) 탐색
3. 미발견 시 [N]초마다 범위 확장
4. 최대 [N]초 경과 시 → 범위 내 최적 상대 매칭 or 대기 중단 안내
```

### 알려진 제약사항
- 서비스 초기 (DAU 낮음) 매칭 시간 증가. 봇 매칭 대안 필요

- FCM(Firebase Cloud Messaging) / APNs 기반 푸시 발송
- 로컬 알림 (에너지 충전 완료 등 타이머 기반)
- 알림 수신 동의 / 카테고리별 On/Off 설정
- 딥링크 연동 → MOD-DEEPLINK 참조

### 알려진 제약사항
- iOS 알림 권한은 런타임 요청 필수 (첫 실행 시 UX 설계 필요)
- Android 13+ 는 POST_NOTIFICATIONS 권한 별도 요청 필요

## 모듈 상세 — MOD-RATING: 평점 요청

**재사용 등급**: ⭐⭐⭐ | **의존 파트**: CL

### 제공 기능
- 인앱 평점 요청 다이얼로그 (Apple SKStoreReviewRequest / Google In-App Review API)
- 요청 트리거 조건 설정 (세션 수, 특정 이벤트 이후)
- 중복 요청 방지 (요청 후 N일 쿨다운)

### 알려진 제약사항
- 플랫폼 API 호출 횟수 제한 있음 (iOS: 연 3회, Android: 기준 없으나 남용 시 노출 안 됨)
- 요청 시점은 사용자 긍정 경험 직후가 효과적 (레벨 클리어, 업적 달성 등)

## 모듈 상세 — MOD-DEEPLINK: 딥링크

**재사용 등급**: ⭐⭐ | **의존 파트**: CL

### 제공 기능
- 유니버설 링크 (iOS) / 앱 링크 (Android) 처리

### 알려진 제약사항
- iOS 유니버설 링크는 HTTPS AASA 파일 서버 호스팅 필요
- Android 앱 링크는 SHA-256 서명 fingerprint 서버 등록 필요

## 장르 확장 포인트 (MOD)

> 모듈 카탈로그에서 장르·특성에 따라 선택적으로 포함하거나 추가할 모듈:

| 장르 / 특성 | 필수 모듈 | 선택 모듈 | 제외 가능 모듈 |
|-----------|---------|---------|-------------|
| 온라인 소셜 게임 | AUTH, INV, IAP, ACH, QUEST | CHAT, MATCH | — |
| 오프라인 전용 | (서버 모듈 전체 제외) LOC | — | AUTH, CHAT, MATCH |
| 멀티플레이어 PvP | AUTH, MATCH | CHAT, ACH | — |
| 가챠/컬렉션 | AUTH, INV, IAP, ACH | QUEST | MATCH |
| 방치형(Idle) | AUTH, INV | ACH, QUEST | MATCH, CHAT |
| 퍼즐 캐주얼 | (서버 없을 시 최소 구성) LOC | ACH | AUTH(게스트 전용 가능), CHAT, MATCH |

### 장르 전용 추가 모듈 (신규 문서화 필요)

아래 모듈은 기본 카탈로그에 없으나 특정 장르에서 자주 필요하므로 해당 프로젝트에서 신규 작성:

| 모듈 ID | 모듈명 | 해당 장르 |
|--------|-------|---------|
| MOD-SEASON | 시즌 패스 | 온라인 게임 전반 |
| MOD-GUILD | 길드/클랜 | 소셜 RPG, MMO |
| MOD-REPLAY | 리플레이 저장 | 레이싱, 액션 |
| MOD-PUZZLE | 퍼즐 상태 관리 | 퍼즐 |
| MOD-WAVE | 웨이브 관리자 | 타워 디펜스, 서바이벌 |

## E 문서 작성 가이드 (MODULES)

> 이 파트의 E 문서(실제 프로젝트 모듈 계획 문서)를 작성할 때 아래 기준을 따르세요.

### 필수 포함 섹션

| 섹션 ID | 섹션명 | 완성 기준 |
|--------|--------|---------|
| MOD-LIST | 프로젝트 사용 모듈 목록 | 사용/미사용 여부 모두 확정, 미사용 시 이유 명시 |
| MOD-[각 모듈 코드] | 사용 모듈 상세 | 통합 방식·버전·커스터마이징 범위 확정 |

### 최소 완성 기준 (Definition of Done)

- [ ] 모든 `[대괄호]` 플레이스홀더 제거됨
- [ ] `[TBD]` 항목에 이유 명시 (해결 시점 포함)
- [ ] 크로스 파트 의존 항목 `[WARNING]` 태그 확인
- [ ] 프로젝트 사용 모듈 전체 목록 — 활성화/비활성화 여부 확정
- [ ] 신규 필요 모듈 — "장르 전용 추가 모듈" 목록 참조 후 추가 여부 결정
