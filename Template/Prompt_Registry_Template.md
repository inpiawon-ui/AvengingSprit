# 프롬프트 레지스트리 — 템플릿 (스튜디오 표준)

> **역할**: 이미지 생성 에셋의 **프롬프트·스펙을 툴 무관하게 영속 저장**하는 스튜디오 표준 포맷.
> 프롬프트가 진짜 자산이다. 스타일이 프로젝트마다 바뀌어도 이 레지스트리는 재사용된다.
> **새 프로젝트 시작 시**: 이 템플릿을 `Projects/[ProjCode]/[ProjCode]_PromptRegistry.md`로 복사 → 아래 "프로젝트 스타일 base"만 그 게임에 맞게 교체 → 에셋 생성할 때마다 한 줄씩 추가.

---

## 0. 생성 워크플로우 — ChatGPT 단일 티어

**이 스튜디오는 리소스를 ChatGPT로 생성한다. ComfyUI는 사용하지 않는다.**
리소스 생성은 **사용자가 ChatGPT에서 직접 수행**하며, 이 리포의 책임은 **프롬프트·규격·배치 설계까지**다.

### 규칙

1. **모든 에셋은 text2img로 새로 생성**한다. 다른 이미지를 img2img/edit 레퍼런스로 넣지 않는다 — 입력의 품질·구조에 앵커링되어 네이티브 퀄 상한이 입력에 묶인다.
2. **세트 일관성**(아이콘 세트·단계별 스프라이트)은 **완성본끼리 레퍼런스**로 잡는다. 히어로 1장을 먼저 확정하고, 후속 생성의 **톤 레퍼런스**로 넣는다. (품질을 끌어올리는 용도가 아니라 톤을 맞추는 용도)
3. **배치(batch) 생성이 기본이다.** GPT는 출력 크기가 고정(1024×1024 / 1024×1536 / 1536×1024)이라 `28×28` 같은 정확한 px를 요청할 수 없다. 작은 아이콘을 개별 생성하면 횟수 낭비 + 스타일이 매번 흔들린다.
   → **한 장에 그리드로 몰아서 뽑고 잘라 쓴다.** 시트 레이아웃(어느 칸이 어느 에셋인지)을 프롬프트에 명시한다.
4. 레퍼런스 목업이 있으면 **말로 정리해 프롬프트에 반영**한다. 목업 이미지를 그대로 넣지 않는다.

### ⚠️ 픽셀아트 주의 (스타일이 도트일 때)

GPT 계열은 **정통 픽셀 도트에 약하다** — 안티앨리어싱이 끼고 매끈해진다.
도트가 정체성인 프로젝트는 **후처리를 파이프라인에 포함**해야 한다.

```
생성(크게) → 배경 제거 → 정수 배율 다운스케일(Nearest/Point)
           → 색 수 양자화(팔레트 상한 적용) → 규격 크롭 → 9-slice 경계 지정
```

- 다운스케일은 반드시 **Nearest**. Bilinear·Lanczos를 쓰면 도트가 뭉개진다.
- 배율은 **정수**로만 (`×2`·`×3`·`×4`). 비정수 배율은 픽셀 격자를 깨뜨린다.
- 색 수 양자화는 스타일 가이드의 **색 수 상한**을 따른다.

## 1. 프롬프트 구조 — subject 1벌 + style base 1벌

같은 subject를 여러 번 쓰되 **스타일은 한 곳에서만** 관리한다.

```
gpt_prompt = gpt_style_base + subject(자연어) + 출력 지시
```

- **GPT 프롬프트는 자연어 서술 한 문단**이다. 가중치(`(tag:1.2)`)·네거티브 개념이 약하다.
- 금지 요소는 네거티브가 아니라 **긍정 서술로 우회**한다. ("no blur" ✗ → "crisp hard edges" ✓)
- 배경 처리·여백·정렬 같은 **출력 지시**를 문단 끝에 고정 문구로 붙인다.

## 2. 프로젝트 스타일 base (← 새 프로젝트가 교체하는 유일한 부분)

```
[gpt_style_base]   그 게임의 스타일을 자연어 한 문단으로
[gpt_output_rule]  배경·여백·정렬 등 공통 출력 지시 (모든 프롬프트 끝에 붙임)
[palette]          핵심 색 HEX + 색 수 상한
```

> **스타일 락 먼저**: "도트냐 페인터리냐"를 base에 못박고 시작한다. 도중에 바꾸면 이전 에셋이 전부 어긋난다.

## 3. 에셋 레지스트리 표 (에셋마다 한 줄)

| 필드 | 의미 |
|------|------|
| `id` | 에셋 ID = 파일명(확장자 제외) = (가능하면) UI 요소 이름 |
| `subject` | 주제 서술 (툴 공통 — comfy·gpt가 공유) |
| `size` | 최종 픽셀 규격 |
| `transparent` | 투명 PNG 여부(Y/N) |
| `tier` | `draft`(현재 소스) / `final`(고퀄 교체 완료) |
| `comfy_workflow` | 사용 워크플로우 체인 |
| `comfy_seed` | 재현용 seed |
| `gpt_ref` | final 생성 시 톤 레퍼런스로 쓸 에셋 id (일관성용, 없으면 —) |
| `path` | 결과 파일 경로 |
| `status` | OK / 재작업 필요 |

```
| id | subject | size | transp | tier | comfy_workflow | comfy_seed | gpt_ref | path | status |
|----|---------|------|:------:|:----:|----------------|-----------|---------|------|--------|
```

> 전체 comfy/gpt 프롬프트는 `base + subject`로 조립되므로 표에는 subject만 둔다.
> draft→final 교체 시 `tier`를 `final`로 바꾸고 `path`를 갱신한다. (Unity 임포트·슬롯 교체는 클라팀)

---

## 4. 새 프로젝트 적용 절차
1. 이 파일을 `Projects/[ProjCode]/[ProjCode]_PromptRegistry.md`로 복사.
2. §2 스타일 base 3종을 그 게임에 맞게 교체(스타일 락).
3. 에셋 생성할 때마다 §3 표에 한 줄 추가(생성=레지스트리 기록).
4. 폴리시: `tier=draft` 중 눈에 띄는 것만 골라 `gpt_prompt`(=gpt_base+subject)로 final 생성 → `tier=final`·`path` 갱신.

> 이 워크플로우·포맷은 **스튜디오 표준**이므로 프로젝트가 바뀌어도 그대로 상속된다. 바뀌는 건 §2 base와 §3 데이터뿐.
