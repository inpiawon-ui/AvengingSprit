# 이펙트(FX) 규칙

> 진행 순서는 스킬 `fx-art-pipeline`. 이 문서는 「무엇으로 · 어떻게」의 기준이다.
> 출처: AVSR 2026-10-08 ~ 10-22 PD 결정을 게임과 상관없는 꼴로 옮겼다.

## 0. 기준은 「어울리는가」
- 아래 표는 출발점일 뿐, 최종 판단은 **화면에 어울리는가**다. 화풍(도트 · 일러스트 …)으로 보여야 맛이 나는 것은 그림이 맞을 때가 많다.
- 파티클을 쓸 때도 입자는 그 게임 화풍의 질감으로 맞춘다. 매끈한 고해상도 빛이 화풍 위에 둥둥 뜨면 실패다.
- 애매하면 그림안 · 파티클안을 같은 화면에 나란히 GIF 로 만들어 비교하고 고른다.

## 1. 무엇으로 만드나 (출발점 — 최종은 고른 시안의 화풍)
| 이펙트 성격 | 만드는 방식 | 예 |
|---|---|---|
| 형태 없이 퍼지는 빛 · 입자 | 파티클 + 빛 셰이더(가산) | 아우라 · 반짝임 · 번짐 · 불씨 · 연기 · 먼지 · 속도선 · 충격파 |
| 형태가 있는 그림 | 프레임 그림 발주 | 덩굴 · 사슬 · 문양 · 하트 · 화살표 |
| 둘이 섞인 것 | 형태는 그림, 둘레 빛은 파티클 | 카드가 몸에 깃듦(문양 + 빛 알갱이) |

- 입자 텍스처는 발주한 그림을 쓴다. 도형 스크립트로 찍지 않는다.
- 파티클은 움직임 · 수 · 수명 · 크기 곡선 · 색 곡선으로 예쁘게 만든다 — 이게 Claude 의 몫이다.
- 빛을 그림 시트(분홍 바탕 → 뚫기)로 받으면 부드러운 번짐이 사라진다. **빛은 검은 바탕 가산으로 받거나 셰이더로.**
- 색은 브리프 「색의 뜻」 표, 세기는 「장면 분위기」 표에서 가져온다.

### 1-1. 파티클 성능 (모바일)
- 새 파티클은 그 게임의 **공용 파티클 풀에 종류를 더해** 쓴다. 터질 때마다 `ParticleSystem` · `GameObject` 를 새로 만들지 않는다.
- 한 번 터질 때 알갱이는 **기본 40개 이하.** 넘으면 이유를 가이드에 적는다(최상위 등급 · 보스 격파 같은 큰 박자만).
- 상시 루프(팝업 장식 · 오브젝트 빛)는 **prewarm** — 창이 열리자마자 다 찬 상태로. 비어 있다 차오르면 「팍」 터지는 것처럼 보인다.
- 화면 밖 · 닫힌 창의 루프는 멈춘다.

## 2. 그림에 빛을 굽지 않는다
- 아이템 · 상자 · 금화 같은 **물건 그림은 빛 · 아우라 · 반짝이 없이** 받는다. 빛은 이펙트로 따로 낸다.
- 이미 빛이 박힌 그림이 있으면 빛 뗀 그림을 발주해 갈아 끼운다(원본은 지우지 않는다).

## 3. 연출에는 이유와 순서가 있어야 한다
- **이유 없는 빛 금지.** 「무엇을 얻었나 · 무엇이 일어났나」가 읽히지 않으면 빼는 것이 낫다.
- **방향이 이야기다.** 산다 = 돈(HUD) → 물건 → 캐릭터 → 효과. 고른다 → 고른 것 포커스 → 창 닫힘 → 캐릭터에 효과.
- 보상은 **창을 닫고 캐릭터 위에서** 잠깐 멈춰 보여 준다(무엇을 · 얼마나).
- 팝업 장식은 **은은하게 계속 도는 것**. 열 때 한 번 「팍」, 테두리 전부 금빛은 금지.
- 이펙트는 **게임 정보(글자 · 숫자 · 아이콘)를 가리지 않는다.** 칸에 붙는 빛은 칸 그림 위 · 글자 아래.
- 물건 뒤 · 앞 깊이를 정한다. 애매하게 반쯤 덮이면 물건 **뒤**로.
- 등장 연출은 이징 곡선(OutBack · OutCubic · OutBounce 등). 숫자 배율을 그대로 박지 않는다.
- **연출로 게임을 멈춘 듯 만들지 않는다** — 방 어둡게 · 적 가라앉히기 금지. 강한 연출은 그 순간 하나에만.

## 4. 코덱스와 같이 정한다
- 새 리소스 · 새 이펙트 · 크게 바꿀 때는 만들기 전에 코덱스와 상의 1회(방식 · 순서 · 크기 · 색 · 깊이 · 발주 사양), 받은 것 검수 1회.
- 같은 주제 여러 회차 핑퐁 금지. 코덱스 의견과 내 판단이 다르면 둘 다 PD 에게 보인다.
- 최종 구현 · 게임 반영 · 검증 · PD 보고는 Claude 가 한다.

## 5. 숫자보다 그림이 먼저
- 연출 가이드(박자표 · **강약**) → 코덱스 시안 → PD 확인 → 제작. 숫자(알파 · 크기)부터 만지지 않는다.
- 상의서에 PD 의 싫어함만 앞세우지 않는다(코덱스가 「최소」로 쏠린다). 목표 모습을 먼저 적는다.
- 게임에 넣기 전에 **움직이는 GIF**(실제 크기 · 배경 · 색)로 PD 확인. 넣은 뒤 녹화해 프레임 단위로 확인.
