# 검증 · 보고 규칙 (L2 `rules/game/checklist.md` 에 더해서)

> L2 체크리스트의 「검증 경로 규칙」(UI 는 UI 로 조작해 확인)과 「사용자에게 넘기기 전에」는 그대로 따른다. 이 문서는 그 위에 얹는다.
> 출처: AVSR 2026-10 실측(카드 녹화 · 이펙트 검수 · 세이브 사고).

## 1. 못 잰 것은 통과가 아니다
결과는 **통과 / 우려 / 반려 / 미검** 중 하나로 말한다. 볼 것 · 잴 것이 없어 판단을 못 했으면 **미검**이다 — 「문제 없음」이 아니다.
- 점검이 아무것도 못 찾았을 때, **찾을 대상이 있었는지**부터 본다(파일 0개를 훑고 「경고 없음」이라 하지 않는다).
- 시험 조건이 안 맞아 효과가 아예 안 났으면 미검이다 — 몸 조건이 달라 카드가 꺼진 채 찍힘 · 체력이 문턱 위라 방벽이 안 섬(AVSR 카드 녹화).
- 보이는 것을 바꾼 일은 **게임에서 실제로 보고(녹화 · 캡처) 남긴 뒤에만** 통과다. 이펙트 · 움직임은 정지 스샷이 아니라 움직이는 것(GIF · 영상)으로.
- 미검을 보고할 때는 무엇이 없어서인지 · 언제 채울지 같이 적는다.

## 2. 찍힌 것을 확인한다 — 파일이 아니라
- 영상 · 캡처를 넘기기 전에 **내용을** 본다(영상 22개가 스킬이 봉인된 채 찍힌 적이 있다). 많으면 프레임을 뽑아 몸 주변을 잘라 크게 본다.
- 실제 게임 칸 크기에서 본다 — 큰 시트에서 멀쩡해도 작은 칸에서 눌린다.
- 화면 캡처는 낡은 화면을 줄 때가 있다 — 가능하면 라이브 데이터(값 · 상태)로 같이 확인한다.
- 글자는 **모든 언어 · 모든 문장**을 넣어 본다(비활성 TMP 는 `isTextOverflowing` 이 늘 거짓 — `GetPreferredValues` 로 잰다).

## 3. 게임 안 검증 녹화 (패턴)
기능 · 카드 · 스킬 · 보스처럼 「게임에서 효과가 나는지」를 볼 때:
1. 실제 판에 들어가 **조건을 세운다**(몸 · 적 배치 · 체력 · 이동 · 스킬 사용) — 효과가 날 조건인지 먼저 따진다.
2. **실제 UI 로** 고른다(레벨업 창 단추 등) — 내부 함수를 바로 부르면 창이 안 닫힌 채 찍힌다(AVSR 카드 녹화 1차).
3. 녹화 + **전 · 후 수치 로그**(화면만으로 안 읽히는 수치 카드용).
4. 한 장씩 영상을 보고 판정을 적어 검수 페이지로 묶는다(영상 · 수치 · 판정 한 줄).
5. 큐로 여러 건을 돌릴 때는 「줄이 남았는데 플레이가 꺼져 있으면 다시 켜는」 감시를 둔다(재시작이 한 번 빠져 멈춘 적이 있다).

## 4. 세이브 · 설정은 되돌린다
- 시험 전에 세이브 폴더를 **복사**해 두고, 끝나면 시험 세이브는 `SaveData_test_<날짜>` 로 옮기고 원본을 되돌린다. **지우지 않는다.**
- 녹화 · 시험으로 바꾼 에디터 설정(언어 등 PlayerPrefs)은 끝에 원래 값으로 되돌린다.

## 5. 보고
- 첫 줄에 결론(판정). 증거(영상 · 캡처) + **파일 경로**를 같이 — 파일만 보내고 경로를 빼지 않는다.
- 무엇을 확인했고 무엇을 확인 못 했는지 나눠 적는다.
