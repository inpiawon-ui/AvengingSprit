# 화면 맞춤 규칙 — 해상도 · 가로 앵커 · 글자 넘침

> ⚠ L2 `refs/game/project/05_prefabs.md` 의 「비율 < 1.778 → match 0」 규칙은 **틀렸다**(태블릿에서 아래가 잘린다). **이 문서가 이긴다.**
> 출처: AVSR 2026-09-01 태블릿 잘림 · 2026-10-12 3언어 넘침. L2 에 고쳐 올릴 후보(키트 `CHANGES.md`).

## 1. CanvasScaler — 다 들어오는 쪽으로 맞춘다 (contain)
가로 · 세로 배율을 각각 재고 **작은 쪽**을 고른다. 기준 해상도의 모든 칸이 화면 안에 남는다.
```
scaleByWidth  = Screen.width  / referenceResolution.x
scaleByHeight = Screen.height / referenceResolution.y
scaleByHeight < scaleByWidth  →  match = 1 (Height 기준, 좌우 여백)
그 외                          →  match = 0 (Width  기준, 상하 여백)
```
- **비율 문턱값(1.778 등)으로 가르지 않는다.** 태블릿에서 match = 0 은 상하 여백이 아니라 **상하 잘림**이다.
  게다가 비율을 `width/height` 로 재면 세로 화면에서는 언제나 0.5625 라 갈림길이 죽어 있었다.
- 기준 해상도는 **스케일러에서 읽는다**(코드에 다시 적지 않는다).

## 2. 가로 앵커 — 왼쪽에 못 박지 않는다
- 루트의 직속 자식은 가로 **가운데(anchorX 0.5)** 또는 **스트레치(0 ~ 1)**. `0 ~ 0` 이면 기준 폭보다 넓은 화면(태블릿)에서 통째로 왼쪽으로 쏠린다.
- 고치는 법(직속 자식만): `anchorX 0 → 0.5`, `x 기존값 − 기준폭/2`, `sizeDelta` 다시 넣기. 한쪽에 붙는 요소는 가운데 앵커로 옮긴 뒤 제 오프셋을 유지한다.

## 3. 글자는 삐져나가지 않는다 — 모든 언어
- 글자 칸은 **그림 속 보이는 상자 안쪽**(테두리에서 3~4 px 안)으로 잡는다. 그림 PNG 를 재서 옮긴다.
- 긴 글자는 TMP 자동 크기(최소를 충분히 낮게). 최소에서도 안 들어가면 칸 · 문구를 고친다.
- 점검은 **모든 언어 · 전 문장**. 비활성 오브젝트는 `isTextOverflowing` 이 늘 거짓 — `GetPreferredValues(text, 폭, 0)` 로 최대 → 최소를 내려가며 잰다.
- 그다음 게임 화면을 캡처해 눈으로도 본다. 해상도별 검증은 UI 키트(`Tools/ui-mockup-kit`)의 하네스로.
