# AVSR 원작 사운드 사용처 매칭

이 폴더(`Assets/BundleResource/Sounds/`)의 원작 음원이 **원작 어디에서 쓰였는지**와, **현재 프로젝트의 챕터·호스트·보스·화면 중 어디에 대응하는지**를 정리한 문서다.
원본 추출 기록은 [`Projects/AVSR/AVSR_SoundExtract.md`](../../../Projects/AVSR/AVSR_SoundExtract.md)에 있다.

**근거 등급**

| 등급 | 뜻 |
|---|---|
| **확정** | 원작 프로그램 코드나 통제 실험, 실제 게임 화면이 뒷받침한다 |
| **추정** | 한쪽 근거만 있거나 정황이다. 원작 영상으로 한 번 더 확인하는 게 좋다 |
| **미확인** | 이번 조사에서 관측하지 못했다 |

- 파일명 숫자 = 원작 사운드 번호 (`bgm_02` = BGM 2번, `sfx_19` = SFX 19번).
- 원작 코드는 같은 효과음을 연달아 낼 때 번호를 NN ↔ NN+24로 번갈아 보낸다. 40–62번은 16–38번과 **같은 소리**라서 파일이 따로 없다.

### 1.3 호스트 (빙의 캐릭터)

## 3. 조사 방법

1. **원작 게임 구동**
   - ROM에 입력 보호 MCU 덤프가 없어 원래는 게임이 진행되지 않는다.
   - 메인 프로그램 **복사본**의 MCU 대기 루틴 2곳(`$fd6`, `$ffa`)을 "쓰고 바로 읽기"로 패치했다.
   - 읽는 값은 MAME Lua가 선택값(`0x37` 시스템, `0x35` P1, `0x36` P2, `0x33`/`0x34` DSW)에 맞는 입력 포트 값으로 돌려준다.
   - 원본 ROM 폴더는 수정하지 않았다.
2. **사운드 요청 기록**
   - 모든 소리는 `$2bcc`(논리 ID → 명령 변환 후 큐 적재)를 거친다.
   - 큐에 들어가는 순간 다음을 기록하고 스냅샷을 찍었다.
     - 호출한 코드 주소
     - 스테이지 `$79582` · 구역 `$79583`
     - 빙의 호스트 `$7a51e`
     - 소리를 낸 객체의 종류(+0x10)
3. **범위 확보**
   - 스테이지·구역 번호를 쓰기 탭으로 강제해 스테이지 1–6과 모든 보스방에 바로 진입했다.
   - 코인·스타트·무작위 이동·연사로 자동 플레이를 돌렸다.
4. **호스트 공격음 통제 실험**
   - 빙의 순간 게임이 `$7a51e`에 쓰는 값을 지정 번호로 바꿨다. 원작은 매 프레임 이 값을 플레이어 객체 종류로 복사하므로(`$d1ce`) 공격 동작도 그 호스트의 것이 된다.
   - 원작 호스트 1–26을 스테이지 1에서 각 120초, 근접·마법형은 적이 많은 스테이지 3·4에서 각 180초 돌렸다. 공격 버튼은 3초 누름 / 3초 뗌을 반복했다.
   - 캐릭터는 HUD 초상화 몽타주와 원작 스프라이트 시트로 판정했다.
   - 전체 에뮬레이션은 병렬로 약 5시간 분량이다.
5. **정적 분석**
   - BGM 선택표 `$2b46`
   - 논리 ID 표 `$2c18` (ID = 사운드 번호)
   - 호스트 피격음 표 `$162ea`
   - 스크립트 명령 스캔
6. 재현 도구: [`Projects/AVSR/_sound_extract/usage/`](../../../Projects/AVSR/_sound_extract/usage/)
